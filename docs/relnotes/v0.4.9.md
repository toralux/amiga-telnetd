Line editor with command history, instant session teardown, and a
hardware-verified console-handlers fix. Full gauntlet validated on an
A500 (68000, AmiTCP_NG 4.1.7).

## Downloads

- `telnetd` - 68000 (stock A500/A2000; also runs on accelerators)
- `telnetd.020` - 68020/030/040/060 accelerators (integer code only, no FPU required). Compile-verified; not yet runtime-tested on accelerated hardware.

## What's new

- Line editor on the telnet console: command history (up to 16 lines),
  arrow-up/down recall, left/right editing, wrap-aware redraw.
- Reconnect after a dropped client is now ~0.5 s (was ~7.6 s in v0.4.8).
- A hung-up session's port is retired at once; no drain delay, and
  hung-up shells now end on their own instead of lingering.
- The helper closes its inherited SYS_Input/SYS_Output handles around
  the synchronous System() call.

## Fixes

- ACTION_DISK_INFO: dp_Arg1 is now converted from a BPTR before the
  InfoData is written (v0.4.8 wrote 36 bytes at a quarter of the
  address), and the reply returns all-NULL pointers per the AUX:
  convention. Pagers such as More follow ID_VolumeNode/ID_InUse to
  detect screen dimensions and require NULL there on a windowless
  console. More worked under v0.4.8 only by accident; the reply is
  now correct by design, verified on hardware (full-screen pager,
  clean streaming).
- Console input: the MSG_PEEK spin loop is replaced by a drain-into-
  queue design; EWOULDBLOCK (35) is handled as a benign would-block.
- One shared timer request serves all WaitForChar timeouts.
