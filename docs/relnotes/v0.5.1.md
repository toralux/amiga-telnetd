CONWINDOW: optional real-window-size paging for More, plus console
window bounds reporting. Hardware-validated on an A500 (68000,
AmiTCP_NG 4.1.7), including two concurrent telnet clients paging at
different window heights.

## Downloads

- `telnetd` - 68000 (stock A500/A2000; also runs on accelerators)
- `telnetd.020` - 68020/030/040/060 accelerators (integer code only, no FPU required). Compile-verified; not yet runtime-tested on accelerated hardware.

## What's new

- New `CONWINDOW` switch: start `telnetd CONWINDOW` and size-aware
  programs such as `More` page by the telnet client's real window
  height instead of their built-in 24-line default. Each session
  reports its own size (NAWS), so concurrent clients with different
  window heights each get correct paging; resizing the terminal is
  picked up live. With CONWINDOW, ACTION_DISK_INFO answers like CON:
  a real (invisible) Intuition window and a ConUnit kept in step with
  the client screen.
- Console window bounds reporting: a program asking for the window
  size (the console "window status request") now gets an answer, as
  CON: gives. Always on, independent of CONWINDOW.
- Better terminal emulation: the cursor row is tracked through
  program output (line feeds, wraps, cursor movement sequences), and a
  program's form feed now clears and homes the client screen like an
  Amiga console does, instead of scrolling one line.

Without `CONWINDOW` nothing changes: `more` keeps paging at 24 lines.
