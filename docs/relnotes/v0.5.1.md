Real-window-size console: More pages by the telnet client's actual
window height, by default. Hardware-validated on an A500 (68000,
AmiTCP_NG 4.1.7), including two concurrent telnet clients paging at
different window heights.

## Downloads

- `telnetd` - 68000 (stock A500/A2000; also runs on accelerators)
- `telnetd.020` - 68020/030/040/060 accelerators (integer code only, no FPU required). Compile-verified; not yet runtime-tested on accelerated hardware.

## What's new

- The console now answers ACTION_DISK_INFO like CON: does: size-aware
  programs such as `More` page by the client's real window height
  (from NAWS) instead of their built-in 24-line default. Each session
  reports its own size, so concurrent clients with different window
  heights each get correct paging, and resizing the terminal is picked
  up live. This is on by default; start with `NOCONWINDOW` to get the
  old behaviour (More paging at a fixed 24 lines). The console hands
  programs a real (invisible) Intuition window, so tools that follow
  the pointers land in valid structures.
- Console window bounds reporting: a program asking for the window
  size (the console "window status request") now gets an answer, as
  CON: gives.
- Better terminal emulation: the cursor row is tracked through
  program output (line feeds, wraps, cursor movement sequences), and a
  program's form feed now clears and homes the client screen like an
  Amiga console does, instead of scrolling one line.

If the latest binary misbehaves on your setup, grab the previous
